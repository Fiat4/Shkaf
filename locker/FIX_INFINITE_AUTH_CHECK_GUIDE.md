# 🔒 Исправление бесконечной проверки авторизации в useAuthCheck

## 🐛 Проблема была в том, что:

**Интерсептор в `useAuthCheck` пытался обновить токен для запроса `/admin/check`**, что создавало бесконечный цикл:
1. `useAuthCheck` вызывает `/admin/check`
2. Получает 401 ошибку
3. Интерсептор пытается обновить токен через `/admin/refresh`
4. Но `/admin/check` снова получает 401
5. Цикл повторяется бесконечно

## ✅ Что исправлено:

### **Исключение `/admin/check` из обновления токена**
```typescript
if (error.response?.status === 401 && !originalRequest._retry) {
    // Проверяем, не является ли это запросом на проверку токена
    if (originalRequest.url?.includes('/admin/check')) {
        console.log('useAuthCheck: Это запрос проверки токена, не обновляем');
        return Promise.reject(error);
    }
    
    // Только для других запросов пытаемся обновить токен
    // ...
}
```

## 🔄 Как теперь работает:

### **При проверке авторизации (`/admin/check`):**
1. `useAuthCheck` делает запрос на `/admin/check`
2. Если токен валиден - пользователь авторизован
3. Если токен недействителен - получает 401 и **НЕ пытается обновить**
4. `ProtectedRoute` редиректит на логин

### **При других API запросах:**
1. Запрос получает 401 ошибку
2. Интерсептор **автоматически обновляет токен** через `/admin/refresh`
3. Повторяет оригинальный запрос с новым токеном
4. Пользователь не замечает обновления

## 🧪 Как тестировать:

### 1. **Обновите страницу** в браузере
### 2. **Перейдите на защищенный маршрут** (например, `/admin`)
### 3. **Проверьте, что не зависает** на "Проверка авторизации..."

## 🎯 Ожидаемый результат:

Теперь система должна:
- **Не зависать** на "Проверка авторизации..."
- **Быстро определять статус** авторизации
- **Обновлять токены** только для обычных API запросов
- **Работать стабильно** без бесконечных циклов
